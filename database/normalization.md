# 정규화 (Normalization)

## 내가 공부 전 아는 상식
* 정규화는 DB 테이블을 잘 나누는 작업이다.
* 중복 데이터를 줄이는 것과 관련이 있다.

## 왜 하는가 (면접 핵심)
정규화를 하지 않으면 **이상현상(Anomaly)** 이 발생한다.

| 이상현상 | 설명 | 예시 |
|---|---|---|
| 삽입 이상 | 불필요한 데이터를 함께 넣어야 삽입 가능 | 수강신청 없이 학생 등록 불가 |
| 삭제 이상 | 데이터 삭제 시 다른 필요한 데이터도 같이 삭제됨 | 수강 취소했더니 학생 정보도 사라짐 |
| 갱신 이상 | 중복된 데이터 중 일부만 수정되어 불일치 발생 | 같은 교수 이름이 여러 행에 있는데 하나만 수정 |

→ 정규화는 이런 이상현상을 없애기 위해 테이블을 올바르게 분리하는 과정

## 1NF (제1정규형)
**규칙:** 모든 컬럼 값이 원자값(더 이상 쪼갤 수 없는 단일 값)이어야 한다.

❌ 위반:
| 학생 | 과목 |
|---|---|
| 이대중 | 수학, 영어 |

✅ 해결:
| 학생 | 과목 |
|---|---|
| 이대중 | 수학 |
| 이대중 | 영어 |

## 2NF (제2정규형)
**규칙:** 1NF 만족 + **부분 함수 종속 제거** (기본키의 일부에만 종속된 컬럼 분리)

복합 기본키(학생ID, 과목ID)가 있을 때, 과목명은 과목ID에만 종속 → 별도 테이블로 분리

❌ 위반: (학생ID, 과목ID) → 성적, 과목명  ← 과목명은 과목ID에만 종속
✅ 해결: 수강 테이블(학생ID, 과목ID, 성적) + 과목 테이블(과목ID, 과목명)

## 3NF (제3정규형)
**규칙:** 2NF 만족 + **이행 함수 종속 제거** (기본키 → A → B 관계 분리)

학생ID → 학과ID → 학과명 인 경우, 학과명은 학생ID에 직접 종속된 게 아님 → 분리

❌ 위반: 학생(학생ID, 학과ID, 학과명)
✅ 해결: 학생(학생ID, 학과ID) + 학과(학과ID, 학과명)

## 역정규화 (Denormalization)
정규화를 너무 많이 하면 JOIN이 많아져서 **조회 성능이 떨어진다.**
→ 성능이 중요한 경우, 의도적으로 중복을 허용해 테이블을 합치는 것

- 정규화: 데이터 무결성 우선
- 역정규화: 조회 성능 우선

## 면접 한 줄 답변
> "정규화는 데이터 중복을 제거하고 삽입·삭제·갱신 이상현상을 방지하기 위해 테이블을 올바르게 분리하는 과정입니다. 다만 JOIN이 많아지면 성능이 저하될 수 있어, 조회가 많은 테이블은 역정규화를 고려합니다."

## 프로젝트 적용
- 팡팡팡: 사용자·진단·알림 테이블을 도메인별로 분리 → 3NF 수준 유지
- 애완용품샵: 주문·상품·유저 테이블 분리, 외래키로 연결
